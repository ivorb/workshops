# Task 02 - Test the agent in the Foundry portal and in Visual Studio Code

## Introduction

In this task, you validate that the Zava product help agent works before you write any client code. This matters because Maya and Ethan need confidence that the agent can answer grounded questions and analyze supporting data before Zava Assist is extended into additional workflows.

## Description

You test the agent directly in the Foundry portal first, and then in Visual Studio Code by using the Foundry Toolkit extension. This gives you a fast way to verify the shared agent behavior in both the portal and developer tooling.

## Success Criteria

- The agent answers grounded questions in the Foundry portal.
- The agent analyzes the uploaded CSV file by using code interpreter.
- The agent is visible in Visual Studio Code under the shared project.
- You can chat with the same agent in the VS Code Agent Builder experience.

## Key Tasks

### 01: Test the agent in the Foundry portal

1. In the chat interface on the right side of the playground, enter the following prompt:

    ```text
    What's the policy for password resets?
    ```

1. Review the response.

    The agent should reference the uploaded document and provide an answer grounded in the attached content.

1. Enter the following prompt:

    ```text
    How do I request new software?
    ```

1. Review the response and observe how the agent uses the grounding data.

1. Enter the following prompt to test code interpreter:

    ```text
    Can you analyze the system performance data and tell me if there are any concerning trends?
    ```

1. Review the response.

    The agent should use code interpreter to analyze the CSV file and provide insights about the data.

1. Enter the following prompt:

    ```text
    Create a chart showing CPU usage over time from the performance data
    ```

1. Review the response.

    The agent should use code interpreter to generate a visualization.

    > **Tip**: If the app fails because the rate limit is exceeded, wait a few seconds and try again.

### 02: Install and configure the VS Code extension

1. Open Visual Studio Code.

1. Select **Extensions** from the left pane, or press **Ctrl+Shift+X**.

1. Search for the `Foundry Toolkit for VS Code` extension from Microsoft and select **Install**.

    Installing the Foundry Toolkit extension adds the Foundry Toolkit experience to Visual Studio Code.

    > **Note**: The extension is currently listed as **Foundry Toolkit**, but some Visual Studio Code labels, commands, or older screenshots may still refer to **AI Toolkit**. In this exercise, treat those names as referring to the same extension experience.

1. After installing the extension, select the Foundry Toolkit icon in the sidebar.

1. Sign in to your Azure account if you're prompted.

### 03: Test the agent in VS Code

1. Under **Microsoft Foundry Resources**, choose **Set Default Project**.

    If a default project is already active, the project name appears in the resources list. You can select a different project by selecting the same **Select project** icon.

1. Select the shared workshop project associated with `ai-zava-foundry`.

1. Expand the project section. Under **Prompt Agents**, locate the `zava-product-help-agent` that you created in the portal.

1. Select the agent name to open the Agent Builder interface.

    The agent playground opens in Visual Studio Code, allowing you to interact with the agent without leaving the development environment.

1. In the playground chat pane, enter the following question:

    ```text
    What is the policy for reporting a lost or stolen device?
    ```

1. Review the response.

    The agent should use the grounding data that you uploaded earlier to provide a relevant answer.

    > **Tip**: You can use this built-in playground to quickly test your agent's instructions and knowledge without writing any code.

1. Verify that the same shared Zava agent is available and responsive in both the Foundry portal and Visual Studio Code.

    This confirms that the workshop environment is ready for the programmatic integration in the next task.
