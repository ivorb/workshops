# Task 04 - Validate the Zava agent from the client application

## Introduction

In this task, you verify that the programmatic client can use the same grounded agent capabilities that you tested earlier in the portal. This matters because Zava Assist ultimately needs a reusable application layer that can call the agent consistently across channels.

## Description

You run a series of prompts against the client application to test file search, code interpreter, and generated output handling. You then close the app and clean up the workshop resources to avoid unnecessary cost.

## Success Criteria

- The running app answers a grounded question from the uploaded file.
- The app performs analysis against the uploaded CSV file.
- The app generates at least one chart or output file in the `agent_outputs` folder.
- You exit the app, deactivate the Python environment, and remove the resources created for the exercise when you're finished.

## Key Tasks

### 01: Test file search and code interpreter from the app

1. In the running application, enter the following prompt to test file search:

    ```input
    What's the policy for password resets?
    ```

1. Review the response.

    The agent should answer by using the uploaded grounding file.

1. Enter the following prompt to request data analysis:

    ```input
    Analyze the system performance data and identify any periods where CPU usage exceeded 80%
    ```

1. Review the response.

    The agent should use code interpreter to analyze the CSV file.

1. Enter the following prompt to request a visualization:

    ```input
    Create a line chart showing memory usage trends over time
    ```

1. Review the response and note any file path printed in the terminal.

    The application saves generated charts and cited files to the `agent_outputs` folder and prints the local file path in the terminal.

1. Enter the following prompt for statistical analysis:

    ```input
    What are the average, minimum, and maximum values for disk usage in the performance data?
    ```

1. Review the response.

1. Enter the following prompt for combined analysis:

    ```input
    Find any correlation between high CPU usage and memory usage in the performance data
    ```

1. Review the response.

    Observe how the agent uses both file search for grounded questions and code interpreter for analysis requests.

    > **Tip**: If the app fails because the rate limit is exceeded, wait a few seconds and try again.

### 02: Close the app and clean up the workshop resources

1. In the running application, type the following command to end the chat session:

    ```input
    exit
    ```

1. When you've finished testing, deactivate the Python environment by running:

    ```bash
    deactivate
    ```

1. In the Foundry portal, navigate to the shared project associated with `ai-zava-foundry`.

1. Select **Settings** > **Delete project**.

1. Alternatively, delete the entire resource group from the Azure portal.

1. If you delete the resource group, open the [Azure portal](https://portal.azure.com), locate `rg-zava-workshop`, and delete it.

    Deleting the project or the resource group helps you avoid unnecessary Azure charges after the workshop.

1. Verify that the resources are scheduled for deletion before you finish.

    If you're continuing to the next exercise immediately as part of the workshop, keep the shared resources only if your instructor or delivery guidance specifically requires them.
