# Task 03 - Review endpoints and project resources

## Introduction

Zava's developers need to understand how applications connect to the Foundry project and its underlying Azure resources. In this task, you review the operational and administrative views so you can identify the resource-level and project-level details that matter in later exercises.

## Description

In this task, you open the **Operate** and **Admin** experiences in Microsoft Foundry portal, inspect the parent resource, and note the key connection details that developers use when building applications.

## Success Criteria

- You open the **Operate** center successfully.
- You review the **Admin** page and the parent resource details.
- You identify the key, project endpoint, and Azure OpenAI endpoint for the project.

## Key Tasks

### 01: Open the Operate center

The operation center is where you can monitor projects, view alerts, monitor agent performance and quotas, and manage resources.

1. In the Foundry portal, select **Operate** in the top menu bar.

![Screenshot of the Operate center page in Foundry portal.](https://raw.githubusercontent.com/MicrosoftLearning/mslearn-ai-studio/main/Instructions/media/ai-foundry-operate.png)

1. Review the operation center page.

### 02: Review project and resource administration details

The **Admin** page helps you distinguish between the shared Foundry resource and the individual project that sits within it.

1. In the left navigation pane, select **Admin**.

1. Review the details page.

   - The *resource* level relates to the **Foundry** resource that was created in Azure to support the project. This resource includes connections to Foundry Services and models, and provides a central place to manage user access to AI development projects.
   - The *project* level relates to the individual project, where you can add and manage project-specific resources. A resource can support multiple projects, and the first one created is the resource's *default* project.

![Screenshot of the Admin page in Foundry portal.](https://raw.githubusercontent.com/MicrosoftLearning/mslearn-ai-studio/main/Instructions/media/ai-foundry-admin.png)

1. Verify that you can see both the project-level and resource-level information for `ai-zava-foundry`.

### 03: Open the parent resource and note connection details

Later exercises use these connection details when applications and tools connect to the shared workshop environment.

1. Select the link to the **Parent resource** associated with the project.

1. Review the resource configuration details page.

![Screenshot of a Foundry resource details page.](https://raw.githubusercontent.com/MicrosoftLearning/mslearn-ai-studio/main/Instructions/media/ai-foundry-resource.png)

1. Note that the Foundry resource has an *endpoint* through which client applications can access resource-level functionality, such as Foundry tools that are shared across all projects in the resource.

1. Select **Home** in the top menu bar to return to the project home page.

1. Note the following values on the project home page:
   - The key
   - The project endpoint
   - The Azure OpenAI endpoint

1. Review how each value is used:
   - The *key* is used for key-based authentication to models and tools, though in most production scenarios you should consider using Microsoft Entra ID authentication based on authenticated user and application identities.
   - The *project endpoint* is used to access models provided directly in Foundry, including OpenAI models, by using the OpenAI **Responses** API and to access Foundry-specific APIs such as the Foundry Agent service.
   - The *OpenAI endpoint* is used to access models by using OpenAI APIs, including the **Chat Completions** API and the **Responses** API.

1. Keep these details available for later exercises in the workshop.

You should now understand the difference between Zava's shared resource context and the specific project context that applications use.
