# Task 04 - Test the omnichannel agent workflow

## Introduction

Zava's stakeholders need evidence that the assistant can move beyond simple chat and support grounded product guidance, data interpretation, and richer assisted commerce patterns. Testing the agent from code helps you validate the full developer workflow.

## Description

In this task, you run several prompts against the client application to verify file search and code interpreter behavior. You then close the app and clean up the project resources to avoid unnecessary costs.

## Success Criteria

- The client app responds to multiple prompts.
- The agent answers grounded questions and performs data analysis.
- Generated charts or files are saved to the `agent_outputs` folder when applicable.
- You exit the app and clean up the project resources.

## Key Tasks

### 01: Test file search and code interpreter from the app

Now test the application by using prompts that exercise different agent capabilities.

1. In the running terminal application, enter the following prompt to test file search:

    ```text
    What's the policy for password resets?
    ```

1. Review the response.

    The agent should answer by using the uploaded grounding file.

1. Enter the following prompt to request data analysis:

    ```text
    Analyze the system performance data and identify any periods where CPU usage exceeded 80%
    ```

1. Review the response and confirm that the agent uses code interpreter to analyze the CSV file.

1. Enter the following prompt to request a visualization:

    ```text
    Create a line chart showing memory usage trends over time
    ```

1. Review the response.

    The application should save generated charts and cited files in the `agent_outputs` folder and print the local file path in the terminal.

1. Enter the following prompt for statistical analysis:

    ```text
    What are the average, minimum, and maximum values for disk usage in the performance data?
    ```

1. Review the response.

1. Enter the following prompt for combined analysis:

    ```text
    Find any correlation between high CPU usage and memory usage in the performance data
    ```

1. Review the response and observe how the agent combines file access, analysis, and reasoning.

    > **Tip**: If the app fails because the rate limit is exceeded, wait a few seconds and try again.

### 02: Exit the application and close the Python environment

After testing, close the app cleanly.

1. In the running application, type the following command and press Enter:

    ```input
    exit
    ```

1. Confirm that the application ends and returns you to the terminal prompt.

1. Deactivate the Python environment by running:

    ```bash
    deactivate
    ```

### 03: Clean up workshop resources

If you've finished exploring the Azure AI services used in this exercise, delete the resources you created to avoid incurring unnecessary Azure costs.

1. In the Foundry portal, navigate to your project.

1. Select **Settings** > **Delete project**.

1. Confirm that you want to delete the project.

1. If you no longer need the shared workshop resources and you are authorized to remove them, open the Azure portal and view the contents of the `rg-zava-workshop` resource group.

1. On the toolbar, select **Delete resource group**.

1. Enter `rg-zava-workshop` and confirm the deletion.

    > **Important**: Only delete `rg-zava-workshop` if you are sure no one else still needs the shared workshop resources, including `ai-zava-foundry`, `aoai-zava-shop`, `cv-zava-shop`, `stzavaworkshop`, and `appi-zava-shop`.

You have now extended Zava's visual product finder into an agent-based omnichannel shopping assistant workflow by configuring an AI agent in Microsoft Foundry, validating it in Visual Studio Code, and connecting to it programmatically from Python.
