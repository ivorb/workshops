# Task 02 - Create and test a document analyzer for care reporting

## Introduction

Contoso Health analysts need structured details from scanned documents so they can combine supporting evidence with the patient feedback trends you created in the previous exercise. In this task, you create a custom analyzer that extracts fields from a document and returns them in a reusable, report-friendly structure.

## Description

You create a Content Understanding Studio project, define a custom schema, test the schema against a sample file, and then build a reusable analyzer. You keep the technical workflow unchanged while framing the output as structured document data that Contoso Health can use in quality reporting.

## Success Criteria

- You have created a custom project that uses `contosohealth-ai` and `contosohealthstorage`.
- The blob container `contosohealth-docs` is used for the project files.
- Your schema includes the required fields, including `TotalQuantity`.
- You have tested the schema successfully and reviewed extracted field values.
- You have built and tested the `invoiceanalyzer` analyzer.

## Key Tasks

### 01: Create the document analysis project

You start by creating a custom schema project in Content Understanding Studio. This project stores the sample files and schema definition used to build the analyzer.

1. In Content Understanding Studio, select the **Get started** button in the custom projects section, and then select **Create**.
1. Select **Extract content and fields with a custom schema**, and then create a project with the following settings:
   - **Project name**: `Invoice analysis`
   - **Description**: `Extract data from an invoice`
   - **Advanced settings**
     - **Connected resource**: *Confirm `contosohealth-ai` is selected*
     - **Connect storage account**: `contosohealthstorage`
     - **Blob container**: `contosohealth-docs`

1. Wait for the project to be created.

   > **Tip**: If an error accessing storage occurs, wait a minute and try again. Permissions for a new resource may take a few minutes to propagate.

### 02: Upload the sample document and configure the schema

You now define the fields that the analyzer should extract. The template provides a starting point, and then you refine it to match the output you want.

1. Upload the `invoice-1234.pdf` file from the folder where you extracted the content files.

   Content Understanding classifies your data and recommends analyzer templates based on the uploaded content.

1. In the **Choose a template** window, select the **Invoice** template and select **Save**.

   The **Invoice** template includes common fields found in invoices. You can use the schema editor to remove fields you don't need and add any custom fields that you do.

1. In the list of suggested fields, select **BillingAddress**. This field is not needed for the uploaded format, so use the **Delete field** (**&#128465;**) icon that appears at the end of the selected field row to delete it.
1. In the top bar of the schema tab, select **Suggest**. This examines the sample file and suggests which fields should be part of your schema. Expand the **Items** field to see which subfields are suggested. Adding those fields replaces your existing schema, so be careful in your projects if you've already edited a schema. Select **Save**.
1. Use the **+ Add new field** button to add the following field, selecting **Save** (**&#10003;**) for the new field:

   | Field name | Field description | Value type | Method |
   |--|--|--|--|
   | `TotalQuantity` | `Total number of items on the invoice` | String | Auto |

1. Verify that your completed schema looks like this, and then select **Save**.

![Screenshot of the invoice analyzer schema in Content Understanding Studio showing fields such as VendorName, InvoiceDate, SubTotal, Items, and TotalQuantity.](https://raw.githubusercontent.com/MicrosoftLearning/mslearn-ai-information-extraction/main/Instructions/Exercises/media/invoice-schema.png)

### 03: Test the schema and review extracted fields

Before you build the analyzer, test the schema on the sample document to confirm that the fields are extracted as expected.

1. Select the **Test** tab, and then select **Run analysis** to test your schema. Wait for analysis to complete.
1. Review the analysis results, which should look similar to this:

![Screenshot of invoice analysis test results in Content Understanding Studio showing extracted field values from the sample invoice.](https://raw.githubusercontent.com/MicrosoftLearning/mslearn-ai-information-extraction/main/Instructions/Exercises/media/invoice-analysis.png)

1. View the details of the fields that were identified in the **Fields** pane.

   At this point, you have validated the schema design before turning it into a reusable analyzer.

### 04: Build and test the reusable analyzer

Now that the schema works, you build the analyzer so it can process similar files consistently and return structured JSON output for downstream use.

1. Select the **Build analyzer** button at the top, and then build a new analyzer with the following properties, typed exactly as shown:
   - **Name**: `invoiceanalyzer`
   - **Description**: `Invoice analyzer`

1. When the analyzer has been built, select **Jump to analyzer list** to view all built analyzers, and then select the **invoiceanalyzer** link. The fields defined in the analyzer's schema are displayed.
1. In the **invoiceanalyzer** page, select the **Test** tab.
1. Upload `invoice-1235.pdf` from the folder where you extracted the content files, and then run the analysis to extract field data from the document.

   The document being analyzed looks like this:

![Image of an invoice number 1235.](https://raw.githubusercontent.com/MicrosoftLearning/mslearn-ai-information-extraction/main/Instructions/Exercises/media/invoice-1235.png)

1. Review the **Fields** pane, and verify that the analyzer extracted the correct fields from the test document.
1. Review the **Results** pane to see the JSON response that the analyzer would return to a client application.
1. Close the **invoiceanalyzer** page to return to the analyzer list.
