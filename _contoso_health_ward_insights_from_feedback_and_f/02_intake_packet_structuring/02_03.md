# Task 03 - Build a custom analyzer for intake-style documents

## Introduction

Contoso Health needs to turn scanned intake documents into structured data that registration and care coordination teams can use without manual transcription. In this task, you create a custom document analyzer that extracts specific fields from a sample document and then validate it on a second file.

## Description

You create a custom project in Content Understanding Studio, attach `stcontosohealthworkshop`, upload a sample PDF, start from the **Invoice** template, and refine the schema. You then build an analyzer and test it on a second sample file to confirm that the extracted fields can be returned to downstream applications as JSON.

## Success Criteria

- A custom project is created by using `stcontosohealthworkshop`.
- The schema includes the required fields and excludes the unnecessary field.
- The analyzer `invoiceanalyzer` is built successfully.
- The analyzer returns structured field values when tested with the second sample PDF.

## Key Tasks

### 01: Create the custom document project

1. In Content Understanding Studio, select the **Get started** button in the custom projects section, and then select **Create**.

1. Select **Extract content and fields with a custom schema**, and then create a project with the following settings:

    - **Project name**: `Invoice analysis`
    - **Description**: `Extract data from an invoice`
    - **Advanced settings**
        - **Connected resource**: Confirm the Foundry resource associated with `ai-contosohealth-foundry` is selected
        - **Connect storage account**: Select `stcontosohealthworkshop`
        - **Blob container**: Create a new container named `content-understanding`

1. Wait for the project to be created.

> **Tip**: If an error accessing storage occurs, wait a minute and try again. Permissions for a new resource or container may take a few minutes to propagate.

1. Verify that the project opens successfully and that the storage account connection is in place.

### 02: Upload the sample document and define the schema

1. Upload the `invoice-1234.pdf` file from the folder where you extracted the sample content files. In this workshop, use it as a stand-in for a structured intake-related document that operations wants to process consistently.

1. In the **Choose a template** window, select the **Invoice** template, and then select **Save**.

1. In the list of suggested fields, select **BillingAddress**.

1. Use the **Delete field** (**&#128465;**) icon that appears at the end of the selected field row to delete **BillingAddress**.

1. In the top bar of the schema tab, select **Suggest**.

1. Expand the **Items** field to review the suggested subfields.

1. Select **Save** to accept the suggested schema update.

1. Use **+ Add new field** to add the following field, selecting **Save** (**&#10003;**) after you enter it:

    | Field name | Field description | Value type | Method |
    |--|--|--|--|
    | `TotalQuantity` | `Total number of items on the invoice` | String | Auto |

1. Verify that your completed schema looks like this, and then select **Save**.

![Screenshot of the invoice analyzer schema in Content Understanding Studio showing fields such as VendorName, InvoiceDate, SubTotal, Items, and TotalQuantity.](https://raw.githubusercontent.com/MicrosoftLearning/mslearn-ai-information-extraction/main/Instructions/Exercises/media/invoice-schema.png)

1. Select the **Test** tab, and then select **Run analysis**.

1. Wait for the analysis to complete.

1. Review the analysis results, which should look similar to this:

![Screenshot of invoice analysis test results in Content Understanding Studio showing extracted field values from the sample invoice.](https://raw.githubusercontent.com/MicrosoftLearning/mslearn-ai-information-extraction/main/Instructions/Exercises/media/invoice-analysis.png)

1. In the **Fields** pane, inspect the extracted values and verify that the expected fields are identified.

### 03: Build and test the document analyzer

1. Select **Build analyzer** at the top of the page.

1. Build a new analyzer with the following properties, typed exactly as shown:

    - **Name**: `invoiceanalyzer`
    - **Description**: `Invoice analyzer`

1. When the analyzer has been built, select **Jump to analyzer list**.

1. In the analyzer list, select the `invoiceanalyzer` link.

1. On the `invoiceanalyzer` page, select the **Test** tab.

1. Upload `invoice-1235.pdf` from the folder where you extracted the sample content files, and then run the analysis to extract field data from the document.

1. Review the sample document that is being analyzed:

![Image of an invoice number 1235.](https://raw.githubusercontent.com/MicrosoftLearning/mslearn-ai-information-extraction/main/Instructions/Exercises/media/invoice-1235.png)

1. In the **Fields** pane, verify that the analyzer extracted the correct fields from the test document.

1. In the **Results** pane, review the JSON response that the analyzer would return to a client application.

1. Close the `invoiceanalyzer` page to return to the analyzer list.

### 04: Verify the document extraction outcome

1. Confirm that the `invoiceanalyzer` analyzer exists in the analyzer list.

1. Confirm that the test run produced both extracted fields and a JSON result.

1. Verify that you can now use the same custom analyzer pattern for structured intake packet extraction scenarios at Contoso Health.
