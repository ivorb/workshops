# Task 02 - Explore prebuilt and document extraction analyzers

## Introduction

Contoso Health needs more than raw text from ward files. Olivia Chen needs reportable fields that can be combined with the patient feedback insights from the previous exercise. In this task, you first compare a prebuilt analyzer with a sample document, and then you create a custom analyzer that extracts specific structured fields from a scanned document.

## Description

You test the prebuilt **Layout** analyzer in Microsoft Foundry, and then switch to Content Understanding Studio to create a custom schema-based analyzer. You use the shared storage resources `contosohealthsa` and `contosohealthdocs`, define the schema, and build the `invoiceanalyzer` analyzer to simulate extraction from scanned ward document content.

## Success Criteria

- You run the **Azure Content Understanding - Layout** analyzer against a sample PDF.
- You create a custom project that uses `contosohealthsa` and `contosohealthdocs`.
- You define and save a schema that includes the required fields.
- You build the `invoiceanalyzer` analyzer.
- You test the analyzer on a second sample file and review the extracted fields and JSON output.

## Key Tasks

### 01: Try the prebuilt Layout analyzer in Microsoft Foundry

Azure Content Understanding includes prebuilt **Read** and **Layout** analyzers that can extract text and structural elements from documents without requiring custom configuration. These analyzers are useful when you need to understand the structure of a scanned ward document before defining custom fields.

1. Return to the [Microsoft Foundry portal](https://ai.azure.com) and make sure the **New Foundry** toggle is on.

1. Select **Build** in the upper-right menu, and then select **Deployments** in the left pane.

1. Select the **AI Services** tab to view the prebuilt models provided by Foundry Tools.

1. Find and select **Azure Content Understanding - Layout**.

1. In the playground, use the option to upload your own data and upload the `invoice-1234.pdf` file from the folder where you extracted the content files.

1. Run the analyzer and wait for analysis to complete.

1. Review the results in both the formatted output and the raw JSON view.

1. Verify that the analyzer extracts text, tables, and structural elements such as paragraphs and sections.

> **Note**: The prebuilt **Read** and **Layout** analyzers extract content from documents without requiring a generative AI model. **Read** extracts text elements such as words, paragraphs, formulas, and barcodes, while **Layout** also extracts tables, figures, document structure, hyperlinks, and annotations.

1. Optionally, go back to the **AI Services** tab and try **Azure Content Understanding - Read** with the same file to compare the results.

### 02: Create a custom project for scanned document analysis

To extract specific operational fields from a ward document, you need a custom analyzer project in Content Understanding Studio.

1. Return to **Content Understanding Studio**.

1. In the custom projects section, select **Get started**, and then select **Create**.

1. Select **Extract content and fields with a custom schema**.

1. Create a project with the following settings:

    | Setting | Value |
    |---|---|
    | **Project name** | `Invoice analysis` |
    | **Description** | `Extract data from an invoice` |

1. Expand **Advanced settings** and confirm the following:

    | Setting | Value |
    |---|---|
    | **Connected resource** | `contosohealth-ai` |
    | **Connect storage account** | `contosohealthsa` |
    | **Blob container** | `contosohealthdocs` |

1. Create the project and wait for it to be ready.

1. Upload the `invoice-1234.pdf` file from the folder where you extracted the content files.

1. In the **Choose a template** window, select the **Invoice** template, and then select **Save**.

### 03: Define and test the document schema

The template provides a starting point, but you refine it to match the structured fields you want to extract.

1. In the list of suggested fields, select **BillingAddress**.

1. Use the **Delete field** (**🗑**) icon that appears at the end of the selected field row to remove the field.

1. In the top bar of the schema tab, select **Suggest**.

1. Review the suggested schema updates, expand the **Items** field to review the suggested subfields, and then select **Save**.

1. Use **+ Add new field** to add the following field, selecting **Save** (**✓**) for the new field:

    | Field name | Field description | Value type | Method |
    |---|---|---|---|
    | `TotalQuantity` | `Total number of items on the invoice` | String | Auto |

1. Save the completed schema.

1. Select the **Test** tab, and then select **Run analysis**.

1. Wait for analysis to complete, and then review the extracted values in the **Fields** pane.

1. Verify that the output includes the expected invoice-style fields and the `TotalQuantity` field.

### 04: Build and test the document analyzer

After you define the schema, you build a reusable analyzer that can be applied to similar scanned documents.

1. Select **Build analyzer** at the top of the page.

1. Build a new analyzer with the following properties:

    | Setting | Value |
    |---|---|
    | **Name** | `invoiceanalyzer` |
    | **Description** | `Invoice analyzer` |

1. Wait for the analyzer to be built.

1. Select **Jump to analyzer list**, and then select the `invoiceanalyzer` link.

1. On the `invoiceanalyzer` page, select the **Test** tab.

1. Upload `invoice-1235.pdf` from the folder where you extracted the content files.

1. Run the analysis to extract field data from the file.

1. Review the **Fields** pane and verify that the analyzer extracted the expected fields.

1. Review the **Results** pane to see the JSON response that the analyzer would return to a client application.

1. Close the `invoiceanalyzer` page to return to the analyzer list.

> **Tip**: In a production healthcare workflow, this same pattern lets Contoso Health extract consistent fields from referral packets, discharge paperwork, or ward reporting forms before those values are added to downstream reporting datasets.
